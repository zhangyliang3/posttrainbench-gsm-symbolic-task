从研究范式到可执行实验

任务档案 GSM-SR / 01 PostTrainBench-like
Harbor task package
合成的不是一条 SFT 样本，而是一道让 Agent 在受限资源下自主完成后训练研究、并能被独立评测的完整任务。
Qwen2.5-Math-1.5B Base 1 GPU / 训练 1 小时 LoRA adapter submission GSM-Symbolic robustness

PostTrainBench 的核心逻辑在给定时间、算力和数据约束下，对指定基座模型开展后训练研究，提交模型或 adapter，并由固定评测程序衡量它在指定 benchmark 上的表现。

核心对象是 Agent 的研究能力。被比较的不是一套预先规定的训练脚本，而是 Agent 在共同边界内作出的研究决策，以及这些决策最终带来的模型能力变化。对任务作者而言，重点是设计可审查的研究环境，而不是替 Agent 写出训练配方。

作者工作 01

设计任务场景

指定 base model、目标能力与下游 benchmark：明确 Agent 要解决的后训练研究问题。

作者工作 02

设定边界与自由度

限定时间、GPU、允许数据和禁止事项；同时保留数据处理、训练方法与超参数的探索空间。

作者工作 03

搭建验收闭环

约定提交模型或 adapter，并由不可修改的固定评测程序加载产物、计算 benchmark 指标。

关于“数据”的边界：训练样本可以是任务输入的一部分，但作者不一定要新造一个训练数据集；必须做到的是明确允许数据的来源与版本、禁止数据以及防止评测泄漏的规则。

Harbor 的核心作用将任务定义转化为一次可执行、可验收的 Agent 运行：按统一契约准备环境、收集提交产物，并在独立 verifier 中产出可比较的评分结果。

因此，Harbor 不只是目录格式；它也是任务的运行与验收框架。它不替作者定义研究问题、数据边界或评分目标——这些仍是“合成题目”的工作。

Agent 结束后收集 adapter；独立 verifier 以固定脚本加载产物、计算指标并写入 reward。

任务场景与定义

我合成的是一道评测 Agent 后训练研究能力的 benchmark task，而不是一个新的数学 benchmark。

它以 GSM-Symbolic 作为固定的下游能力评测：Agent 在受限时间、算力和数据边界内，自主后训练指定 base model，提交 LoRA 与过程证据；独立 verifier 再判断产物的能力与合规性。

研究对象执行 Agent考察它是否能自主提出并实施有效的后训练策略。
固定输入Base + 边界Qwen base、1 GPU、训练 1 小时、合法 train/dev 数据切分。
研究交付LoRA + 证据adapter、最终训练脚本、实际训练 JSONL 与运行摘要。
最终验收独立 verifier审计提交数据后，在固定 750 题上成对比较 base 与 adapter。

GSM-Symbolic robustness

将“稳健性后训练”拆成一组可执行、可审查的设计决策。

PostTrainBench 定义“要评测怎样的后训练研究”；Harbor 定义“如何把这项研究运行并验收”。本题的合成工作，就是把前者的范式逐项翻译成后者的任务包。

A. 从范式到任务包

PostTrainBench 核心

指定研究目标

让 Agent 改善一个指定 base model 在给定 benchmark 上的表现。

本题设计：指定 Qwen2.5-Math-1.5B base，目标是 GSM-Symbolic 中数值替换和条件增加下的稳健性。

Harbor 落地：instruction.md 描述研究目标；/models/base 固定基座。

PostTrainBench 核心

受限下的自主研究

固定时间、算力和数据边界，但不预设训练配方，保留 Agent 的研究决策空间。

本题设计：1 GPU、训练最多 3,600 秒；7,223 条 GSM8K train 可训练，250 条 dev 仅供策略比较。

Harbor 落地：task.toml 声明资源与 allowlist；环境预置两份数据；题面写明训练与开发边界。

PostTrainBench 核心

固定产物与比较

提交后训练产物，并以固定下游协议衡量最终模型能力。

本题设计：提交 PEFT LoRA adapter；Main / P1 / P2 各 250 题，三项宏平均。

Harbor 落地：artifacts 收集 adapter；独立 tests/ verifier 重载 base 并写入 reward.json。

研究目标

在数值替换与条件增加下提升数学推理稳健性。从单一准确率改为观察 Main、P1、P2 的能力退化。

范式继承

保留 PostTrainBench 的 Agent 自主研究结构。不预设训练配方，Agent 决定数据处理、合成、LoRA 和超参数。

资源改编

Qwen2.5-Math-1.5B base、1 GPU、训练 3,600 秒。Agent 阶段最多 4,800 秒，为有限的 development 对照预留时间。

数据边界

7,223 条 GSM8K train 用于训练，250 条 development 仅供比较。GSM8K test 与 GSM-Symbolic 均禁止进入训练。

产物协议

提交可加载的 PEFT LoRA adapter。verifier 重载固定 base，而不是接受完整模型或外部服务答案。

评分协议

Main / P1 / P2 各 250 题，宏平均。三个版本等权，避免题量差异主导总分。

B. 质量控制

让任务的输入、输出与分数可追溯
Data

数据可追溯

训练 / development 固定切分；GSM-Symbolic revision 与 SHA256 锁定，评测文件随 verifier 包提供。

Evaluation

评分可复现

同一 verifier 在同题、同 prompt、贪心解码下评估 base 与 adapter；Main / P1 / P2 分开报分再宏平均。

Isolation

训练与评分隔离

Agent 仅允许 DeepSeek API 与安装 CLI 所需的两个包源；verifier 完全断网，重载原始 base 与提交 adapter 后评分。

Integrity

提交可审计

强制提交训练脚本、实际训练 JSONL 与摘要；对 development / 最终题作数字归一化 n-gram 近重复审查。

有效提交

能力分数可以比较

adapter 可加载、证据齐全、训练数据未命中 development / final eval 重合检查时，报告真实 score 和 delta；即使分数低于 base，仍是有效实验结果。

无效提交

协议失效，而非能力为零

缺 adapter 或提交证据、训练数据格式/记录不一致，或命中近重复审查时，verifier 写数值型 0 分；审计原因另存 submission_status.json。该结果不进入可信比较。

总分为何下降？

Main 仅上升 0.012，但 P1 / P2 分别下降 0.092 和 0.048。总分按三版等权平均，因此 Main 的小幅提升无法抵消条件变化版本的退化。

本次可得结论

未观察到稳健性提升

在当前固定推理与评测协议下，该 adapter 没有展示 GSM-Symbolic 条件变化鲁棒性的提升；它不能作为“后训练有效”的证据。

待验证假设

为什么会这样？

可能是训练数据仍偏原始 GSM8K 题型、训练改变了原题行为却未形成改写不变性，或有限预算下出现过拟合/能力干扰。需结合逐题结果、实际训练数据和 dev 表现判断。

D. 尝试与问题

将障碍、应对与证据状态分开陈述
  1. GPU 运行环境

    问题：普通 AutoDL 容器不支持 Docker，无法直接运行 Harbor trial。

    应对：改用具备 Docker daemon 与 NVIDIA Container Toolkit 的 GPU 主机。

    已验证Docker 容器可识别并使用 GPU。

  2. Harbor GPU 声明

    问题：Harbor 0.23 的默认 Docker provider 拒绝 `gpus = 1`。

    应对：增加 DockerGPUEnvironment，并通过 Compose 显式请求 NVIDIA 设备。

    已验证任务已通过 GPU capability 检查。

  3. 污染与开发反馈

    问题：仅靠题面禁止无法证明训练数据未触及最终评测，Agent 也缺少合法的策略比较信号。

    应对：从 GSM8K train 划出 250 条 development split；要求提交训练脚本、实际 JSONL 和摘要，并在 verifier 做近重复审查。

    已实现development 仅用于策略选择，不进入最终 reward。

  4. 真实 Agent 时限

    问题：首次真实 Agent trial 虽完成 586 步 LoRA 训练，但总时限 3,600 秒耗尽在开发评估，Harbor 未进入最终 verifier。

    应对：将“训练预算”和“Agent 总阶段”拆开：训练最多 3,600 秒，Agent 阶段最多 4,800 秒，并限制 development 对照的范围。

    下一轮验证需以新时限和完整证据重新运行，才能产生有效正式成绩。

  5. Verifier 闭环

    问题：早期 regrade 因 reward JSON 含字符串字段而被 Harbor 拒绝；adapter-only 评测也实测超过 20 分钟。

    应对：reward 仅保留数值字段，审计原因改写入 submission_status.json；固定评测离线提供，且采用 batch size 8 的确定性贪心解码。

    已验证Harbor 已成功解析 reward；历史 adapter 的诊断复评分完成，耗时 23 分 41 秒。

当前结论

已在 RTX 3090 验证：环境构建、GPU 透传、Agent LoRA 训练、development 诊断、离线 verifier、数值型 reward 解析，以及历史 adapter 的诊断复评分。
当前诊断：adapter 0.3947，低于 base 0.4373；它解释了模型行为，但因缺少新协议要求的训练证据而无效。
下一步：以 4,800 秒 Agent 阶段重新运行，提交完整证据并通过重合审查，获得可报告的有效正式成绩。
